How I work

The habits that repeat across every project I run.

Write it down first

A short spec before the code and an ADR for each decision that is costly to undo. The reasons live in the docs; the code says what it does.

One interface for every project

make up, check, pr, deploy and rollback work the same everywhere. Nothing ships unless the full check is green, and a failed deploy rolls itself back.

Pull requests ready to merge

Nothing reaches main without passing the full check, the same one CI runs; a pre-push hook makes it mandatory on my machine too. On top of that:

  • Linting, formatting and strict type checks, plus architecture rules checked by import-linter or architecture tests.
  • Unit tests for the domain, a test for every HTTP endpoint and MCP tool, and integration tests against a real PostgreSQL, tenant isolation included. A bug fix comes with the test that would have caught it, and coverage has a floor that only goes up.
  • A self-review with /code-review, and a /security-review whenever the change touches sessions, permissions, row-level security or keys.
  • A snapshot of the public contract when the API or MCP changes, and before-and-after screenshots when the interface does.
  • A description that says what changed for the user, how it was verified and what wasn't, with the delivery checklist ticked or explained.

Small batches

One branch and one pull request per batch of work, one commit per change, Conventional Commits and a changelog built from fragments, so a release reads like a list of decisions.

Architecture you can test

Domain-driven, hexagonal layers (domain, application, infrastructure, transport) with one action per file. The layer rules are enforced by import-linter and architecture tests, not by goodwill.

Secure by default

Multi-tenant data behind PostgreSQL row-level security, with an isolation test per table and an app that never connects as the table owner. Passwordless login. No secrets or deployment details in git.

AI with hard limits

The model writes SQL but never runs it; engines are read-only; user content stays out of logs; a local model is the default. Paid calls get a cost estimate first, and tests never call a paid API.

Agents as first-class users

Every app exposes an MCP server and a CLI with scoped agent tokens. Team procedures are written as Claude Code skills and hooks, so agents follow the same rules people do.

Measure before claiming

RAG answers are scored against question sets, model changes start with a small pilot, and a report says what was checked and how, not that something "works perfectly".
